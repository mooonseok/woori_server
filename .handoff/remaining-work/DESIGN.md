# 공통 설계 — 확정 사항과 구현 제안

## 유지할 제품과 구조

앱 이름은 우리. 가족·지인 몇 그룹으로 시작한다. 깔끔하고 세련된 사진 갤러리,
큰 사진·여백·읽기 쉬운 글자, 홈/앨범/마이페이지 3개 탭을 유지한다.
새 기능도 v6 기반 UI와 container/view, hooks/services, Atomic 구조를 따른다.
사진 뷰어는 핀치·더블탭·팬을 우선하고 버튼을 늘리지 않는다. 뒤로 가기는 페이지명 없이 아이콘.
검색 펼침·도구 표시·정렬 드롭다운·단계별 가이드에서 포커스와 reduced-motion을 검증한다.
모든 화면에 초기/로딩/실패/권한 없음 상태를 두며 API 실패를 샘플 데이터로 대체하지 않는다.

client: Next.js 정적 export 웹 + 관리자 웹 + 향후 Capacitor 앱.
server: NestJS API + 독립 워커, Prisma/PostgreSQL, OpenAPI 정본.
배포 목표: Railway 유료 API/워커(상시 실행), Supabase Pro, 비공개 R2.
웹 정적 호스팅은 Cloudflare Pages 회원·관리자 프로젝트로 확정했다. 요금·상품 조건·스토어 요건은 실제 적용 시 공식 문서로 재확인한다.

## 공통 보안 경계

- 그룹의 현재 활성 멤버십을 매 요청 검사한다. 인증만으로 사진 접근을 허용하지 않는다.
- 웹은 HttpOnly 세션 쿠키, Origin/CSRF 검사. 서버 DB 역할과 migration 역할은 분리한다.
- RLS의 서버 역할 허용은 사용자별 권한을 대신하지 않는다. 쿼리에서 사용자·그룹 범위를 강제한다.
- 탈퇴/정지/내보내기/사진 삭제와 동시에 진행되는 조회·업로드·푸시를 경쟁 조건으로 검증한다.
- R2는 private, 읽기는 권한 확인 API를 통한다. 원본 URL·토큰·메일 본문을 로그에 남기지 않는다.
- 푸시는 현재 구현의 outbox, 세션 연결, bindingVersion, 발송 lease, 표시 재검증을 재사용한다.
  웹 푸시 구현을 Capacitor 네이티브 푸시 완료로 취급하지 않는다.

## W01 계정 복구와 이름 수정 (2026-10-15 구현)

화면: 로그인 → 아이디 찾기 / 비밀번호 재설정. 이름+이메일만 입력.
일치 계정 유무와 무관하게 같은 202/안내 문구를 돌려주고, 실제 메일만 해당 계정에 발송한다.
HTTP 오류는 요청 제한·서비스 장애처럼 사용자가 대응할 수 있는 범주로 구분한다.
아이디는 메일 본문으로 안내한다. 비밀번호는 원문/임시 비밀번호를 메일로 보내지 않고
일회용 링크를 보내 새 비밀번호를 직접 입력한다. 사용자가 재설정 링크 방식을 확정했다.
이름은 신원 증명이 아니라 조회 보조값이다. 현재 DB displayName과 정규화한 이메일로 조회하며 이름 수정 화면에도 이를 안내한다.

구현 API (contracts/openapi.json 0.7.0):

- `POST /v1/auth/recovery/username` {name,email} → 일반화된 202.
- `POST /v1/auth/recovery/password` {name,email} → 일반화된 202.
- `POST /v1/auth/recovery/password/confirm` {token,newPassword} → 204, 자동 로그인하지 않음.
- `PATCH /v1/auth/profile` {displayName} → 갱신된 사용자. 이메일/아이디 변경을 섞지 않음.

서버: 기존 email_tokens의 purpose에 RESET_PASSWORD를 사용해 인증 용도와 분리한다. 스키마 변경 없이
해시·사용 시각·만료·계정 연결을 저장한다. 유효기간은 30분이며 재요청 시 이전 재설정 링크를 무효화한다.
동일 token 소비·비밀번호 변경·모든 기존 세션 및 연결된 푸시 구독 폐기를 한 트랜잭션으로 처리한다.
성공 후 이전 복구 token도 무효화한다. 두 동시 확인 중 하나만 성공해야 한다.
요청 제한은 IP 및 정규화한 이메일의 해시 등으로 적용하고 원문 이메일을 rate key로 노출하지 않는다.
메일 클릭 GET은 token을 소비하지 않는다. 프리뷰/보안 스캐너에 의해 비밀번호가 변경되면 안 된다.
클라이언트는 token을 저장소/분석 로그에 기록하지 않고 URL에서 읽은 뒤 주소 노출을 줄이며
재설정 페이지의 referrer 정책·외부 리소스를 점검한다.

## W02 그룹 관리

활성 회원 목록/그룹명 수정/탈퇴/내보내기/소유권 이전/그룹 삭제를 단계별로 구현한다.
일반 회원은 자신만 탈퇴, 그룹장은 내보내기 가능. 마지막 그룹장은 소유권 이전 또는 그룹 삭제 후 탈퇴.
소유권 이전 대상은 같은 그룹의 활성 회원이며 서버 트랜잭션에서 기존 소유자와 대상 상태를 재검사한다.
비회원에게 명단을 노출하지 않는다. 권한 상실 즉시 사진·댓글·추억·알림·푸시 대상에서 제외한다.
그룹 삭제는 기존 사진 삭제 큐와 quota 정합성을 재사용하고 대량 객체 삭제를 요청 안에서 끝내지 않는다.
2026-10-15 확정: 앨범 제목 수정은 그룹장만 허용한다. 탈퇴·내보내기는 공유 사진·댓글을 유지한다.
그룹 삭제만 전체 콘텐츠를 즉시 숨기고 기존 워커가 R2 파일을 배치 정리한다. DB 메타데이터는 tombstone으로 유지한다.
그룹장 이전은 기존 초대를 모두 취소한다. 자진 탈퇴 회원은 새 초대로 재참여할 수 있고, 내보낸 회원은 재참여할 수 없다.

## W03 촬영일과 추억 홈

2026-10-15 사용자 확정 및 구현: 수동 촬영일 → EXIF 촬영일 → 업로드일 순서다.
한국 시간은 고정 UTC+09:00으로 계산한다. EXIF offset이 없으면 +09:00으로 해석하며 잘못된 값·미래 날짜는 업로드일로 대체한다.
현재 활성 구성원에게만 오늘/이번 달 추억을 제공한다. 이전 연도만 대상으로 하며 오늘 사진은 이번 달에서 제외한다.
평년의 2월 28일에는 2월 29일 사진도 포함한다. 날짜와 출처를 표시하며 업로더와 그룹장만 수동 날짜를 수정·초기화할 수 있다.
숨김은 개인에게만 적용하며 복원 가능하다. 사진 원본·앨범·다른 가족에게 영향이 없다. 추억 푸시 자동 발송은 후속 작업이다.
기존 사진 EXIF 보완도 사용자 승인 범위다. 서버의 photos:backfill-dates는 기본 dry-run이며 로컬 DB만 허용한다.
--apply는 최대 100장씩 원본을 읽고 처리 직전·저장 시 상태를 재확인하며 수동 날짜를 보존한다. 실패 항목은 재시도 가능하다.
로컬 개발 DB 마이그레이션/최소 권한 적용 승인·완료. 기존 대상은 0장으로 원본 순회는 없었다.
격리 DB의 합성 JPEG 3장과 실제 R2로 EXIF 2장/업로드일 대체 1장, 기존 사진 보완 1장 및 수동 날짜 보존을 검증했다.
운영 DB 적용과 과거 실사진 전수 검증은 수행하지 않았다.

## W04 사진 처리와 모바일 품질

2026-10-15 정책 확정 및 구현: 한 장 30MiB, 한 선택 30장·합계 300MiB, 최대 6천만 픽셀.
같은 선택의 이름·크기·수정시각·타입이 같은 파일만 중복 제외한다. 한도 초과는 접수 전에 거절한다.
원본 EXIF/GPS는 보존하고 다운로드 메뉴에서 안내한다. 감상용·썸네일 메타데이터는 제거한다.
R2 전송 후 별도 process API로 영구 큐에 접수하며 독립 워커가 READY 전환·quota·알림을 처리한다.
기존 complete API는 호환용 동기 방식으로 유지한다. 재시작·재시도·삭제/권한 변경 경합은 통합 검증했다.
화면은 전송/접수/처리/완료/실패를 구분하며 재진입 시 본인 작업만 복구한다. 접수 이후 처리는 화면 종료와 무관하다.
기기에서 R2로 전송하는 동안에는 화면을 열어 두어야 한다. 모바일 백그라운드 전송은 보장하지 않는다.
HEIC PoC에서 현재 sharp/libvips는 메타데이터만 읽고 HEVC 픽셀 디코딩에 실패했다. HEIC는 계속 미지원이며 새 의존성을 추가하지 않았다.
photos:reconcile은 로컬 DB의 사진 행별 prefix만 대조하는 report-only 명령이다. DB 행이 없는 전역 고아 객체 탐색·자동 삭제는 미구현이다.
기한 만료 후 늦게 끝난 처리의 고아 객체가 남을 수 있으므로 보고서만으로 삭제 안전성을 확정하지 않는다.
실제 R2 합성 48MP/EXIF 회전 사진과 Chrome 두 계정은 검증했다. iPhone/Android 실제 선택·저장·공유·위치 댓글 정합성과 배포 메모리 측정은 남아 있어 W04는 진행 중이다.
로컬 개발 DB에는 처리 큐 마이그레이션 적용 완료. 배포는 API와 별도로 워커 상시 실행이 필수다.
되돌릴 때 신규 큐 접수를 중지하고 새 워커로 대기 작업을 완료·실패 처리한 뒤 이전 앱으로 복구한다. 추가 컬럼은 유지한다.

## W05 계정 수명과 서비스 안내

2026-10-15 구현: 로그인 중 비밀번호·이메일 변경 요청은 현재 비밀번호를 재확인한다.
이메일은 새 주소 확인 전까지 기존 주소를 유지하며, 최신 요청의 30분 단회 링크만 허용한다.
확인 시 요청 계정 로그인이 필요하고 명시적 버튼으로 확정한다. GET/메일 미리보기는 변경하지 않는다.
비밀번호 변경·이메일 확정은 전체 세션·푸시 연결·미소비 이메일 토큰을 원자적으로 폐기한다.
클라이언트는 개인 상태를 지우고 재로그인·기기별 알림 재연결을 안내한다.
이메일 확정 후 새 주소는 인증 완료로 처리하고 기존 주소에 통지한다. 통지 실패는 성공한 변경을 되돌리지 않으며 메일 재시도는 W07이다.
추가 DB 구조는 email_tokens.targetEmail nullable 컬럼 하나이며 사용자 승인으로 기존 로컬 DB에 적용했다.
인증된 auth.woori.stream 발신 설정으로 Naver 인증 메일·기존 주소 통지 전달 및 실제 변경·전체 세션/푸시 해제를 검증했다.
데스크톱 Chrome 두 계정은 확인했으며 모바일 너비 검증은 도구 제약으로 미확인이다. 상세 근거와 잔여 범위는 status.json을 따른다.
2026-10-15 회원 탈퇴 정책 확정: 활성 소유 그룹은 이전·삭제 접수 후 탈퇴할 수 있다.
공유 사진·댓글은 유지하며 작성자를 탈퇴한 회원으로 표시한다. 반응도 익명으로 유지한다.
계정 아이디·이메일·이름·비밀번호와 개인 설정/알림/인증 자료는 즉시 정리하고 복구하지 않는다.
기존 관계용 내부 식별자만 남기며 같은 아이디·이메일 재가입은 새 계정으로 취급해 이전 접근권한을 복원하지 않는다.
공유 원본 EXIF·사진·댓글 내용에 담긴 정보는 남을 수 있으므로 탈퇴 전 정리 안내를 제공한다.
미완료 업로드는 취소하고 기존 삭제 큐로 파일을 정리한다.
상태 전환과 접근 차단은 즉시, R2/DB 실제 삭제는 재시도 가능한 작업으로 분리한다.
2026-10-15 서비스 안내 확정·구현(`feature/service-guidance`, OpenAPI 0.15.0): 회원은 게시된 공지만 읽고 공지 작성·문의 답변·신고 처리는 W06 관리자에서 연다.
문의는 본인 작성·조회만, 최근 24시간 5건. 신고는 사진·댓글·회원 대상, 대상당 1회, 24시간 20건이며 운영자만 처리한다. 그룹장·상대에게 알리지 않고 자동 숨김도 없다.
차단은 '나에게만 숨김'이다. 차단한 사람에게만 상대의 사진(앨범 수·커버·추억 포함)·댓글·반응과 상대 활동 알림·푸시가 사라지고, 상대에게 알리지 않으며 멤버십은 바뀌지 않는다(그룹장 내보내기와 별개).
차단 시 기존 상대 활동 알림은 지우고 해제해도 복원하지 않는다. 회원 탈퇴 시 문의는 삭제, 본인 신고는 대상·사유·상태만 남기고 자유 입력 설명은 지운다. 본인 차단 목록은 삭제한다.
운영 주체·보호 책임자·문의처·보관 기간·처리 위탁·시행일·법적 문구는 정하지 않았으며 개인정보 안내에 '확정되면 안내' 자리표시로 둔다. 실기기 모바일 검증은 남아 있다.

## W06 관리자

별도 관리자 인증 audience와 MFA/재인증, 최소 역할 권한을 적용한다.
회원/그룹/앨범 목록은 필요한 메타데이터만 노출하고 사진 열람은 명시적 권한·사유·감사로그가 있어야 한다.
일반 회원 세션의 관리자 호출은 항상 거절한다. 운영자는 비밀번호 원문 조회 불가.
회원 수정·정지·탈퇴 처리는 일반 도메인 정책과 큐를 재사용하고 감사 이벤트에 비밀값을 넣지 않는다.
공지/신고 처리와 운영 지표(처리 큐·메일·푸시 실패·저장량)를 추가한다.

2026-10-15 W06 확정(사용자): 단일 관리자 역할. 관리자는 모든 회원 사진을 볼 수 있으나 사유(5~500자)·최근 10분 재인증(비밀번호+TOTP, 로그인도 재인증으로 간주)·감사로그가 있어야 하며 표시용 파생본만 제공(원본 불가). 이용 정지는 본인 접근(로그인·세션·푸시·업로드)만 막고 공유 콘텐츠는 그룹에 남긴다. 정지 회원은 그룹 멤버 목록에 평소처럼 표시(정지 표시 없음)하고 그룹장이 내보낼 수 있으나 그룹장 넘기기 대상은 아니다. 정지 회원이 그룹장이면 해제 전까지 그룹장 관리 불가(관리자 그룹장 변경은 범위 밖, 알려진 한계). 구현 선택: 관리자 계정·세션·감사 테이블과 쿠키 분리, TOTP(RFC 6238) MFA, 첫 관리자는 서버 CLI(`pnpm admin:create`)로만 생성, 감사로그는 runtime 역할 SELECT/INSERT만.

2026-10-16 W06 구현 확정: 정지 회원은 멤버 목록뿐 아니라 신고·차단 대상과 기존 알림 행위자로도 그대로 유지(정지 여부 비노출, 수신·본인 접근만 차단). 관리자 JSON 요청(GET 포함)은 X-Woori-Request 필수이며, 후속 동영상 스트림 GET/HEAD만 정확한 관리자 Origin·현재 세션에 묶인 서명 티켓을 대신 요구한다. 관리자 웹 origin은 회원 경로에서 거절(영역별 CORS). 상태 변화 없는 변경 요청도 개인 정보를 돌려주면 *_VIEWED 감사, 앨범 사진 목록 조회도 감사. 관리자 로그인(비밀번호+TOTP)은 재인증 창을 갱신. 감사로그·신고·문의 보관 기간은 미정.

## W07 안정성 및 가족 베타 배포

메일 outbox는 인증/복구 메일의 DB 변경과 원자적으로 연결하고 worker 재시작·재시도·만료를 설계한다.
메일 전송에 필요한 token 원문은 hash만으로 재구성할 수 없으므로, payload 암호화와 짧은 보관·폐기를 함께 설계한다.
공급자 timeout 후 재발송 중복을 고려하고 idempotency 지원 여부를 확인한다.
API/worker 각각 health와 실패율, queue lag, DB/R2/메일 장애를 감시한다.
웹과 API 도메인·쿠키 SameSite/Secure·CORS·프록시 hop·R2 PUT CORS를 실제 배포 토폴로지로 검증한다.
새 migration 먼저, 호환되는 API/worker, 웹 순으로 배포하며 파괴적 migration은 별도 절차로 한다.
운영 DB에는 로컬 dev:db:prepare나 통합 테스트를 실행하지 않는다.
DB와 R2 백업을 분리하고 별도 환경에서 복원 훈련으로 접근 제어·참조·사진 실물을 확인한다.
RPO/RTO·보관·비용 한도는 사용자 결정. 알림·반응 묶음 발송 정책은 중복 제거와 함께 결정한다.

2026-10-16 W07 이전 결정(이하 Railway/싱가포르·Railway 비용 한도는 아래 서울 결정으로 대체됨): 회원 웹·관리자 웹은 Cloudflare Pages 정적 호스팅. API·워커(Railway)와 DB(Supabase Pro)는 싱가포르 리전으로 통일(Railway에 서울 리전 없음, DB만 서울이면 쿼리 왕복 지연). 도메인은 Cloudflare에 등록된 woori.stream: 회원 웹 woori.stream, 관리자 웹 admin.woori.stream, API api.woori.stream(같은 사이트라 HttpOnly 쿠키 유지), 메일은 Resend로 mail.woori.stream 하위 발신(SPF·DKIM·DMARC). 백업은 하루 단위: Supabase 일일 백업(7일)과 R2 사진의 별도 백업 버킷 매일 복사, 월 1회 별도 환경 복원 훈련(RPO 24시간, RTO 반나절). PITR은 사용하지 않음. Railway 월 한도 $60, 사용량 알림 $45(다른 공급자 비용 별도).

2026-10-16 W07 최신 인프라 결정(사용자): API·워커는 AWS Lightsail 서울의 별도 인스턴스, DB는 Supabase Pro 서울. API 2GB·워커 4GB는 부하 검증 전 후보이며 자동 결제·서버 생성 승인은 별도다. Cloudflare Pages·비공개 R2·Resend·일일 백업 목표는 유지한다. 기존 Railway 설정 파일은 미사용 참고 자료다. Supabase 운영 DB는 migration 19개·앱 테이블 30개·RLS·woori_api 권한 적용을 완료했다. 실제 Lightsail 배포, TLS 역방향 프록시·접근 제한·재시작·비용 경보·백업 스케줄은 미구성이다.

2026-10-16 W07 알림 묶음·베타 범위 확정(사용자): 업로드 알림은 같은 업로더·같은 앨범 10분 창으로 묶고 첫 사진 후 약 2분 뒤 1회 발송, 추가분은 같은 알림 교체(push tag 동일), 누르면 앨범으로 이동, 방해금지 해제 시 묶음별 1회. 반응 알림은 같은 사진 30분 창으로 묶음("OO님 외 N명"). 베타 전 포함: 앨범 그리드 480px 썸네일(감상용 이미지는 뷰어에서만), 앨범 기간 자동 표시(촬영일 수동→EXIF→업로드일 최소~최대, 한국 날짜, 차단 회원 사진 제외, 직접 편집 없음), 앨범 목록 30개 단위 cursor 더 불러오기. 동영상 업로드도 베타 전 포함: 서버 워커에서 H.264로 변환, 1개당 1분·200MB 이하, 변환 성공 후 원본 삭제(위치 정보 제거·용량 절감), 회원은 변환본 다운로드 가능. 한 번에 고르는 파일 합계 300MB 제한은 동영상에도 그대로 유지(큰 동영상은 한 번에 하나씩, 2026-10-16). 베타 후: 커버 직접 지정, 서버 검색·촬영일순 정렬, 가입 승인제(즉시 참여 유지), 그룹 참여 알림, 추억 자동 푸시, 추가 가이드.
