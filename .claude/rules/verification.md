실행한 검증과 미실행 검증을 구분한다. 기존 실패는 기준 상태에서 재현하고 현재 변경과 분리한다.
사소한 문서 변경은 관련 검사만 실행한다. 기능 변경은 위험에 맞는 단위·통합·브라우저 검증을 수행한다.
pnpm policy:test는 임시 Git 저장소에서 fixture 커밋과 훅을 실행하며 실제 저장소를 커밋/push하지 않는다.
pnpm policy:quality는 전체 검사다. pre-push는 임시 체크아웃을 사용하므로 사용 중인 개발 서버를 중지하지 않는다.
테스트·보안 검사를 삭제/skip하거나 실패 임계값을 낮춰 통과시키지 않는다. 상세 절차는 woori-verify 스킬을 읽는다.
