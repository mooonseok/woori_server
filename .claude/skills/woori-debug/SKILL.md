---
name: woori-debug
description: 오류나 이상 동작을 재현하고 원인을 좁혀 회귀를 확인한다.
---

1. 실제 입력·환경·기준 커밋·호출 경로와 최소 재현 명령을 확보한다. 인증값·개인정보를 출력하지 않는다. 관찰한 오류와 가설을 구분한다.
2. 기존 상태에서도 같은 조건으로 실패했는지 확인해 이번 회귀/기존 실패/환경 문제/미확인을 구분한다. 기준 상태를 검사하지 않았으면 기존 결함이라고 단정하지 않는다. 사용자 변경을 되돌려 기준선을 만들지 않는다.
3. 가설 하나를 확인하는 검사부터 수행한다. 원인이 확인되면 승인된 수정 범위에서 최소 변경한다. 진단만 요청했다면 결과만 보고한다.
4. 같은 실패가 두 번 반복되면 자동 재시도를 멈추고 재현 조건·시도한 방법·원인 근거·다음 선택지를 정리한다. 요구사항이 불명확하면 질문하고, 환경 부족이면 blocked/미검증으로 남긴다.
5. 수정 전 실패/수정 후 성공과 인접 부정 경로를 확인한다. 테스트 삭제·skip·기대값 완화로 실패를 숨기지 않는다. 재현하지 못한 원인은 추정이라고 밝힌다.
6. 결과는 원인/가설, 재현 명령, 수정 범위, 검증 결과, 미확인 사항으로 반환한다. 대량 로그 분석은 verification-runner에 위임할 수 있으나 비밀값이나 원문 로그를 전달하지 않는다.

출처: harness-engineer. 원본 절차를 프로젝트에 맞게 재작성했으며 프레임워크 구조/명명 규칙은 가져오지 않았다.
