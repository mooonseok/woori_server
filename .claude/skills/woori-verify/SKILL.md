name: woori-verify
description: 변경 위험에 맞는 실제 프로젝트 검사와 회귀 검증을 선택하고 결과를 보고한다.
---

1. package.json에서 실제 명령을 확인한다. 문서 변경은 policy:check/policy:test와 관련 포맷으로 충분하다.
2. 로직 수정은 관련 단위/타입 검사, UI 수정은 브라우저 동작, 권한·DB 변경은 격리 통합 테스트를 실행한다.
3. 전체 제출 검증은 pnpm policy:quality를 사용한다. 클라이언트의 같은 .next에 dev와 build를 동시에 실행하지 않는다.
4. 테스트는 경계·실패·경쟁 조건·보안 동작을 확인한다. 구현 문자열을 그대로 복제하는 테스트는 피한다.
5. 실행 명령·결과·미실행 이유를 요약한다. 소유하지 않은 프로세스는 종료하지 않는다.
pre-push는 실제 outgoing commit을 임시 폴더에서 설치·검사한다. 서버는 로컬 DB가 실행 중이고 런타임 역할 준비가 되어 있어야 한다.

출처: engineering:testing-strategy. 원본 절차를 프로젝트에 맞게 재작성했으며 프레임워크 구조/명명 규칙은 가져오지 않았다.
