name: woori-implement
description: 기능 추가와 버그 수정 요청에서 기존 구현을 보존하며 작은 변경과 검증을 수행한다.
---

1. AGENTS.md, 적용 규칙, 현재 Git 상태·diff, 실제 호출부와 인접 테스트를 확인한다. 원래 요구사항과 관찰한 동작의 차이를 수용 기준으로 정리한다.
2. 기준 커밋·기존 실패·허용 파일·금지 작업을 정한다. 간단한 변경은 혼자 처리하고, 위임이 필요하면 독립 조사부터 나눈다. 같은 파일은 한 명만 수정하며 검토 담당에게 구현 파일을 맡기지 않는다.
3. 기존 구조 안에서 가장 작은 수정으로 구현한다. 비동기 취소·중복 요청·오류 복구·권한 및 API 계약 영향을 확인한다. 새 의존성은 실질적인 필요가 있을 때만 검토한다.
4. woori-verify에서 변경 영역의 프로필과 추가 동작 검사를 고른다. 실패는 woori-debug로 원인을 좁혀 수정·재검증하며 테스트 삭제/기대값 완화로 숨기지 않는다.
5. 단순한 변경은 원래 요구사항과 최종 diff를 직접 대조한다. 위임/고위험 작업은 별도 검토 담당에게 원래 요구사항·수용 기준·기준 커밋·최종 diff·검증 근거를 전달한다. 실제 코드 검토의 지적은 구현 담당이 수정하고 영향받은 검사만 다시 수행한다.
6. 수용 기준, 검토 지적, 최종 스냅샷의 검사 결과를 대조한 뒤 변경·근거·미검증을 보고한다. 커밋·push·배포·운영 데이터 변경은 구현 완료에 자동 포함하지 않는다.

출처: harness-engineer. 원본 절차를 프로젝트에 맞게 재작성했으며 프레임워크 구조/명명 규칙은 가져오지 않았다.
