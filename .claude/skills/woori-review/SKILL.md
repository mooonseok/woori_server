name: woori-review
description: 코드 변경의 실제 결함과 보안 또는 회귀 위험을 근거와 함께 검토한다.
---

1. 입력으로 원래 요구사항·수용 기준·기준 커밋·기존 변경·실제 diff·검증 근거를 받는다. 구현 담당의 요약만으로 승인하지 않는다. 입력이 없으면 원본 요청/코드에서 확인하고 핵심 의도가 불명확할 때 질문한다.
2. 실제 변경 코드와 호출부·테스트를 함께 읽는다. 요구사항 누락, 인증/권한, 입력 검증, 비동기 경합, 데이터 정합성, 성능과 회귀 공백을 확인한다.
3. 검토는 읽기 전용으로 수행한다. 코드·DB·외부 상태를 수정하지 않고 수정할 사항은 구현 담당에게 돌려보낸다. Codex 역할 지침의 읽기 전용 원칙은 별도 샌드박스 권한을 의미하지 않는다.
4. 각 발견에는 중요도·파일/행·재현 조건·영향·수정 방향을 붙인다. 확인되지 않은 가설은 미확인으로 표시하고 폴더 구조·명명 선호를 새 규칙으로 강제하지 않는다.
5. 결과는 발견 사항, 수용 기준 충족 여부, 실행/미실행 검사와 남은 위험으로 반환한다. 중대한 결함이 해결되고 필요한 검사가 통과한 경우에만 다음 단계로 넘긴다. 발견 없음은 미실행 검증의 통과를 뜻하지 않는다.

출처: engineering:code-review. 원본 절차를 프로젝트에 맞게 재작성했으며 프레임워크 구조/명명 규칙은 가져오지 않았다.
